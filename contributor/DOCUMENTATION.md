# Changing documentation and SDK examples

[`builder`](../builder/README.md) is what someone building on the SDK reads. Four rules keep it one coherent set:

- **Each kind of content has one home.** A concept a newcomer needs before any code goes in the [Introduction](../builder/INTRODUCTION.md) and nowhere else, so the mental model is taught in one place. A new recipe goes in the [Developer Guide](../builder/DEVELOPER-GUIDE.md), a new method in [Usage](../builder/Usage.md), a new design rationale in [Reactive model](../builder/REACTIVE-MODEL.md) or [State units](../builder/STATE-UNITS.md). A new cache behavior gets a B-number in [Cache semantics](https://github.com/xynolog/protocol/blob/main/contract/CACHE-SEMANTICS.md) and a test that cites it. A change that fits no one home is probably two changes.
- **Code fences are compile-checked.** Every `ts`, `tsx` and `typescript` fence in the builder docs, the skills and the react-ui docs included, is extracted and type-checked by [`checks/doc-snippets/check.mjs`](../checks/doc-snippets/check.mjs), with a pass that catches an `await` on something that is not awaitable. It checks against the SDK packages of the artifact bundle that [`sdk.lock`](../sdk.lock) pins, which CI's `sdk` job builds from that commit and its `doc-snippets` job installs; moving the pin is how the docs move to a newer SDK. Names a snippet does not define come from the prelude at [`checks/doc-snippets/prelude.ts`](../checks/doc-snippets/prelude.ts) (the skills have their own, `prelude-skills.ts`, and the react-ui docs `prelude-ui.ts`): extend the prelude rather than adding boilerplate to a snippet. Mark a fence `ts sketch` only for pseudocode or a display-only shape. Exemptions are counted, and the count should hold or shrink.
- **What the docs name resolves.** [`checks/links/check.py`](../checks/links/check.py) clones, as a reader reaches them, the repositories the docs link, and fails on a link, an anchor, a repository's path in a code span, an `npm run` script or a `make` target that main of the repository it names does not have, and on a link into a repository a reader cannot open. CI's `links` job runs it on every pull request, and daily, since the other repositories move their files without a run here.
- **Wire-level truth lives in [`protocol/contract/`](https://github.com/xynolog/protocol/blob/main/contract/README.md).** [TRANSPORT-CONTRACT.md](https://github.com/xynolog/protocol/blob/main/contract/TRANSPORT-CONTRACT.md) is what every transport honors, [TRANSPORT-HTTP.md](https://github.com/xynolog/protocol/blob/main/contract/TRANSPORT-HTTP.md) the wire over a gateway, and [EVENT-BUS.md](https://github.com/xynolog/protocol/blob/main/contract/EVENT-BUS.md) and [CHANNELS.md](https://github.com/xynolog/protocol/blob/main/contract/CHANNELS.md) the bus and its channels. The builder docs link there and do not restate wire format.

Before changing an SDK itself, read [Reactive model](../builder/REACTIVE-MODEL.md) and [State units](../builder/STATE-UNITS.md) for the constraints a change has to fit, [Cache semantics](https://github.com/xynolog/protocol/blob/main/contract/CACHE-SEMANTICS.md) before touching anything the cache backs, and the protocol docs before touching anything on the wire. The axiom and liveness harnesses in `@xynolog/core/testing/axioms` are the executable half of those docs. The test doubles are at `@xynolog/core/testing`, which needs no `fast-check`.
